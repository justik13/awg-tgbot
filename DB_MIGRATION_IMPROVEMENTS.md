# Улучшения обработки БД при переустановке/обновлении

## Проблема
При переустановке или обновлении бота со старой базой данных отсутствовали:
1. Проверка целостности БД перед миграцией
2. Версионирование схемы БД
3. Логирование процесса миграции
4. Защита от восстановления из повреждённого snapshot

## Внесённые изменения

### 1. `bot/database.py`

#### Новые функции:
- **`get_db_version(db)`** — получение текущей версии схемы БД из таблицы `app_settings`
- **`set_db_version(db, version)`** — установка версии схемы БД
- **`check_db_integrity(db_path)`** — полная проверка целостности SQLite через `PRAGMA integrity_check`

#### Изменения в `init_db()`:
- Добавлена проверка целостности БД перед инициализацией
- Таблица `app_settings` теперь создаётся в начале для хранения версии схемы
- Логирование текущей версии схемы
- Установка версии схемы (`DB_SCHEMA_VERSION = 1`) после успешной инициализации всех таблиц
- Удалено дублирующее создание таблицы `app_settings`

### 2. `awg-tgbot.sh`

#### Новые функции:
- **`sqlite_full_integrity_check(db_file)`** — полная проверка целостности БД через Python (аналог `check_db_integrity` в database.py)

#### Улучшения существующих функций:

**`snapshot_sqlite_runtime_bundle()`**:
- Добавлена проверка целостности исходной БД перед созданием snapshot
- При обнаружении проблем — предупреждение в логе, но snapshot создаётся (для возможности отката)

**`restore_sqlite_runtime_bundle()`**:
- Добавлена обязательная проверка целостности snapshot перед восстановлением
- При обнаружении проблем — восстановление отменяется с ошибкой (защита от порчи данных)

**`migrate_legacy_default_db_path()`**:
- Добавлена проверка целостности старой БД перед миграцией
- При обнаружении проблем целостности:
  - Создаётся аварийный бэкап с суффиксом `.corrupt.backup.YYYYMMDDHHMMSS`
  - Копируются основные файлы БД и сопутствующие `-wal`, `-shm`
  - В логе сохраняется путь к бэкапу
- Добавлено логирование успешной миграции

## Преимущества новой реализации

| Сценарий | Было | Стало |
|----------|------|-------|
| Обновление с сохранением БД | Схема обновлялась, но без проверки целостности | ✅ Проверка целостности + версионирование |
| Переустановка (fast) | БД копировалась без проверок | ✅ Проверка целостности + логирование |
| Миграция старой БД | Копирование без проверок | ✅ Проверка + аварийный бэкап при проблемах |
| Откат из snapshot | Snapshot восстанавливался без проверок | ✅ Проверка целостности snapshot перед восстановлением |
| Диагностика проблем | Нет информации о версии схемы | ✅ Версия схемы хранится в БД и логируется |

## Совместимость
- Все изменения обратно совместимы
- Старые БД без версии схемы автоматически получают версию `0`, затем обновляются до `1`
- Функция `ensure_column()` продолжает работать для добавления новых колонок

## Рекомендации по использованию

### Перед обновлением:
```bash
sudo bash awg-tgbot.sh backup
```

### Проверка состояния после обновления:
```bash
sudo bash awg-tgbot.sh diagnostics
```

### Просмотр логов миграции:
```bash
sudo journalctl -u awg-tgbot -f | grep -i "БД\|integrity\|миграц"
```
